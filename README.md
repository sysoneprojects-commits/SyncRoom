# SyncRoom V1 — first working product package

SyncRoom is an Android-first watch-party app for creating a room, inviting people with a code, synchronizing YouTube playback, opening videos stored on the host device inside SyncRoom, sharing the Android app/screen, chatting and reacting in real time.

The visual system follows the approved SyncRoom concept: cinematic dark navy, blue/violet accent gradient, low-glass surfaces, custom SyncRoom mark, consistent icons and compact mobile-first navigation.

## Included in this V1

- Premium Home screen matching the approved concept.
- Real bottom navigation: **Home / Rooms / Search / Profile**.
- Persistent device user ID and editable display name.
- Recent room history with host marker and one-tap rejoin.

- Local video playback with `video_player` including Android `content://` URIs.
- YouTube playback via the official IFrame-based `youtube_player_iframe` integration.
- Live room screen with:
  - participant list
  - host badge/authority
  - room code invite/copy
  - play/pause
  - ±10 second seek
  - YouTube fullscreen
  - live chat
  - emoji reactions
  - mic/audio-track toggle for an active broadcast
  - subtitle/CC controls, including local `.srt` selection for the host
  - More / leave / start-stop broadcast sheet
- Android app/screen capture with `flutter_webrtc.getDisplayMedia` and foreground execution setup.
- Small-room WebRTC P2P delivery: signaling passes through the room Durable Object while media travels peer-to-peer.

## What is fully wired now

### YouTube room
Each phone loads the same YouTube video. SyncRoom sends only room state (`play`, `pause`, `seek`, timestamp) through the Cloudflare room. The host is the only playback authority. This is the lightest and most reliable V1 mode.

### From Device
The host selects a local video (or opens a video using **Open with SyncRoom**). The movie opens in SyncRoom's player. Press **Start broadcast** to ask Android for app/screen capture permission and send the resulting media stream to room viewers through WebRTC P2P.

The host's private local path is **not sent to other clients**; only a display filename is stored as room metadata.

### Screen Share
The host starts Android screen/app capture from the room. Viewers signal readiness through the Durable Object and receive the WebRTC stream.

## V1 media boundary

The current media fan-out is P2P. It is appropriate for the first real two-phone / small-room test, but host upload grows with every viewer and public STUN alone can fail on restrictive mobile/NAT networks. The production scale-up path is Cloudflare Realtime SFU + TURN.

Android system-audio capture can also vary by Android version, the source app and device policy. SyncRoom requests audio with display media, but protected/DRM audio or protected video cannot be assumed to be capturable.

YouTube captions are available through the YouTube player CC control. Local host video supports selecting an external `.srt` file and overlays the active cue on the video. Full independent room-wide voice chat remains a later media-pass feature; the current Mic control manages the active broadcast audio track.

## Backend setup

### Manual
1. Create a Cloudflare D1 database named `syncroom-db`.
2. Copy `server/wrangler.toml.example` to `server/wrangler.toml`.
3. Put the real D1 database ID into the copied file.
4. From `server/` run:

```bash
npm install
npx wrangler d1 migrations apply syncroom-db --remote
npm run typecheck
npm run deploy
```

### GitHub Actions
Set:
- Secret `CLOUDFLARE_API_TOKEN`
- Secret `CLOUDFLARE_ACCOUNT_ID`
- Repository variable `SYNCROOM_D1_DATABASE_ID`

The workflow creates the runtime Wrangler config, applies D1 migrations and deploys the API.

## Android build

The package intentionally keeps generated Android boilerplate out of the authored source tree. GitHub Actions or a machine with Flutter can reproduce it:

```bash
cd mobile
./scripts/bootstrap_android.sh
flutter build apk --release \
  --dart-define=SYNCROOM_API_BASE=https://YOUR-WORKER.workers.dev
```

Set the GitHub repository variable:
- `SYNCROOM_API_BASE=https://YOUR-WORKER.workers.dev`

The build workflow uploads `app-release.apk` as the `SyncRoom-Android-V1` artifact.

## Room protocol

Client → room:
- `member.join`
- `sync.play`
- `sync.pause`
- `sync.seek`
- `chat.message`
- `reaction`
- `screen.started`
- `rtc.viewer.ready`
- `rtc.offer`
- `rtc.answer`
- `rtc.ice`

Room → clients:
- `state.snapshot`
- `members.snapshot`
- `member.joined`
- `member.left`
- playback sync events
- chat / reaction events
- targeted WebRTC signaling events
